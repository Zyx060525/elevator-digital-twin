## 4.1 基本信息

- **项目名称**：电梯微空间数字孪生：社交距离与交流行为耦合的多智能体仿真与治理优化
- **赛道**：D. 工程设计与数字世界
- **参考方向（可多选）**：数字孪生 / 仿真到现实 / 复杂系统建模
- **项目摘要**：
  高密度密闭微空间（电梯轿厢）中，"物理距离—社会距离—交流行为"三者存在强耦合。
  本项目构建电梯轿厢的多智能体数字孪生，基于 MESA 仿真乘客的人流演化、社交距离偏好
  与交流行为，量化"交流行为对社交距离的调制作用"，并经 Agnes Harness（AGH）完成
  "任务规划—能力调用—反馈处理—结果验证"的仿真到现实闭环，输出面向密闭空间治理与
  社交距离动态优化的策略建议。
- **问题来源与目标**：
  - 来源：后疫情时代高层建筑垂直交通节点的高密度、短时、近距离人流，社交距离难以维持，
    且既有研究多忽视"交流行为"这一主动社交因素对空间距离的反向影响。
  - 目标：① 建立可计算的电梯场域人-空间耦合模型；② 量化交流行为对社交距离的影响；
    ③ 通过 AGH 闭环给出可落地的社交距离优化与密度调控策略。

## 4.2 技术信息

### AGH 作用
Agnes Harness 作为本作品的智能体运行与执行底座，负责调度完整闭环：拆解"优化电梯
社交距离"任务、通过 MCP 调用多智能体仿真能力、解析仿真指标反馈并调整参数、最终验证
并输出策略。全程仅调用 Agnes 模型，不接入任何第三方模型。

### Agnes 模型
- 名称/版本：agnes-3.0-flash（Agnes 3.0 Flash）
- 使用环节：任务规划、能力调用决策、反馈处理、结果验证（全流程）
- 调用方式：经 elevator_twin.agnes_client 调用 OpenAI 兼容 Chat Completions 接口
  （Base URL: https://api.agnes-ai.cn/v1，中国区网关），全程仅调用 Agnes 模型；仿真工具经 MCP 协议调用（elevator-twin MCP server）

### 数据 / 代码 / 专业软件 / 仿真环境 / API / 设备接口
- 代码：Python 3.11，多智能体仿真框架 MESA 2.x
- 仿真环境：电梯轿厢网格化空间（默认 4×4 格，可调），乘客多智能体
- 指标：平均最近邻距离、社交距离违规率、交流对数、交流对平均距离
- API/接口：MCP（Model Context Protocol）工具接口，供 AGH 调用
- 设备接口：无（纯数字孪生仿真，不涉及真实硬件）
- 运行方式：`python -m elevator_twin.run`（详见 README）

## AGH 执行闭环设计（对应 3.1 至少三连续步骤）

| 环节 | AGH/Agnes 行为 | 对应证据 |
|---|---|---|
| ① 任务规划 | 把"优化电梯社交距离"拆分为子任务：确定轿厢尺寸/人数/交流意愿参数、确定评价指标 | AGH 执行记录中的规划输出 |
| ② 能力调用 | 通过 MCP 调用 run_simulation / optimize_social_distance 等工具，驱动 MESA 仿真 | MCP 调用链、工具调用日志 |
| ③ 反馈处理 | 读取指标（违规率/交流对数），判断是否达标，若不达标调整参数（如降低交流诱导、优化密度）并重新仿真 | 多轮仿真参数与指标对比 |
| ④ 结果验证 | 将最终指标与电梯载客规范/防疫距离基准对比，输出策略结论 | 结果对比表、策略建议 |

### 实现落地（已全部可运行）
| 能力 | 命令 | 说明 |
|---|---|---|
| 基础仿真 | `python -m elevator_twin.run` | 单次演示 + 批量对比实验 |
| 增强仿真 | `python -m elevator_twin.model_enhanced` | 真实尺寸(1.6m×1.4m) + 楼层上下客 + 社会力 |
| AGH 闭环 | `python -m elevator_twin.agh_loop` | 经 MCP 真实调用仿真工具，完成四步闭环 |
| 可视化 | `python -m elevator_twin.visualize` | 指标曲线 / 热力图 / 对比图（figs/） |

增强版核心洞察：在真实电梯尺寸（1.6m×1.4m、格边长 0.4m）下，即使乘客最大化距离，
平均最近邻距离仅约 **0.53m**（最小 0.4m），远小于 1.0m 的标准社交距离（违规率恒为 1.0）
——证明"密闭空间社交距离在物理上不可达"，而交流行为会在此基础上进一步压缩距离。

## 三类测试样例（正常 / 边界 / 失败）

### 正常样例
输入：4×4 轿厢、8 名乘客、交流意愿均值 0.5、仿真 30 步（seed=42）。
结果：模型收敛，avg_dist≈1.104、violation≈1.0、chat_pairs≈3，
      空间快照显示乘客分布并形成交流对（如 `P.CC / .P.C / ...C / CC..`）。

### 边界样例
1) 满载边界：4×4 轿厢、16 名乘客（=容量），无空闲格。
   结果：仿真不崩溃，乘客保持原位，violation_rate=1.0。
2) 最低交流意愿：交流意愿均值 0.0。
   结果：chat_pairs 恒为 0，仅社交距离最大化生效。
3) 单人边界：1 名乘客。
   结果：指标不报错，avg_nearest_distance=0、violation_rate=0、chat_pairs=0。

### 失败样例
1) 容量超限：n_passengers=17 > 4×4=16。
   结果：抛出 ValueError「乘客数 17 超过轿厢容量 16」。
2) 非法参数：n_passengers=-1。
   结果：抛出 ValueError「乘客数不能为负：-1」（已做输入校验，避免静默失败）。

## 创新性与发展价值
- **创新点**：① 将"交流行为"作为主动社交变量纳入社交距离模型，量化其对空间距离的
  压缩效应（低意愿 0 交流对 vs 高意愿 4 交流对，平均距离由 1.280 降至 1.0）；
  ② 用 MCP 把仿真能力标准化封装，使 AGH 能"像调工具一样调仿真"，形成真正的
  模型执行闭环。
- **发展价值**：可扩展到地铁车厢、候机厅、教室等密闭/半密闭空间；可接入真实人流数据
  （摄像头/闸机）实现"仿真-现实"数据同化，向真正可治理的数字孪生演进。

## 缺陷修复记录（打包实测中发现并已修复）

| 现象 | 根因 | 修复 | 验证 |
|---|---|---|---|
| 网页首屏样式正常，但下方出现一大片 JS 源码文本，「运行仿真」按钮点击无反应 | `templates/index.html` 的 JS 注释里含**字面量** `</script>`：HTML 解析器在「脚本数据」状态下遇到 `</script` 即提前结束脚本块（写在注释里同样生效），其后的 JS 被当作普通文本显示，`runSimulate / runSweep / runAgnes` 等函数从未定义 | 该注释改写为 `<\/script>`（加反斜杠）并补充说明；`public/index.html` 由 `python build_static.py` 重新生成 | `05_提交证据/证据图/06_前端功能自检.png`：页面无源码泄漏、五个核心函数均为 `function`、`runSimulate()` 真实跑通并渲染出指标卡与曲线；`03_测试样例自检结果.png` 13/13 ALL PASS |
| 已部署 Python 后端（或填入 Render 地址）后，页面**一直显示「浏览器内置引擎（离线）」**，只能手点「重新检测后端」才可能连上 | 旧探测逻辑只在页面加载时探 1 次 `/api/health`（5 秒超时），失败即把 `apiReady` 置为 `false`；而 `callEngine()` 中 `apiReady === false` 会直接短路到内置引擎 —— Render 免费实例冷启动需 30~60 秒，首次探测几乎必然失败且**此后不再重试**；同时后端地址未做规范化/校验（示例占位符 `xxx.onrender.com` 也照存） | 探测结果重构为区分四类原因（纯静态托管 / 超时 / 网络不可达 / 响应不像后端）；显式配置后端地址后按 3s→6s→12s→20s→30s 退避重试（累计约 70 秒，覆盖冷启动），恢复后自动切回「Python 后端引擎」并提示唤醒秒数；仿真请求失败超 15 秒自动复探；新增 `normalizeApiBase()`（自动补协议、去末尾斜杠）与占位符/格式校验（拦下时给内联提示，不再静默刷新）；纯静态托管仍只探一次，不反复打 404 | `docs/offline_parity/e2e_backend_probe.py` 4 场景 39/39：后端迟启动时页面**未刷新、未点按钮**即自动切回 Python 引擎（实测唤醒约 6.6 秒），随后「运行仿真」确实命中 `/api/simulate`（HTTP 200）；`e2e_page.py` 57/57 回归通过 |
