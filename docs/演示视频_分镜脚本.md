## 1. 录制前准备（10 分钟）

1. **环境自检**（都在有 `elevator_twin` 包的目录执行）：
   - `python -m elevator_twin.agnes_client` → 连通性 OK。想录「Agnes 真实调用」就必须先配好 Key（`set AGNES_API_KEY=你的Key` 或 `elevator_twin\.agnes_key`）；
     没配也能录，AGH 会打印「Agnes 模型：未检测到 Key，使用确定性降级逻辑」，**两种念法下面都给了**。
   - `python -m elevator_twin.run` 与 `python -m elevator_twin.agh_loop` 各预热跑一次，确认滚动流畅、数字与脚本一致。
2. **终端**：字号调大（≥16pt）、窗口宽度 ≤100 列、开录前 `cls` 清屏；PowerShell 先执行
   `[Console]::OutputEncoding=[System.Text.Encoding]::UTF8` 防中文乱码（用 `.bat` 则已内置）。
3. **浏览器**：隐藏书签栏（Ctrl+Shift+B）、缩放 100%（Ctrl+0）、关掉无关标签；
   本地 `http://127.0.0.1:5000` 与线上 `https://elevator-digital-twin.netlify.app/` 各开一个无痕窗口；
   提前点过一次「运行仿真」让图表有底数，正式录制时再点一次即可。
4. **画面洁净**：清空桌面无关文件、关闭通知（专注助手）、任务栏只留录制所需图标；
   **绝不能把 `.agnes_key`、环境变量、真实姓名/学号录进画面**（评审核验用截图同理）。
5. **备用素材**：`提交包_电梯微空间数字孪生/05_提交证据/证据图/` 的 6 张 PNG + 4 份日志，
   用于 B-roll 与「等终端滚动」时的垫画面。
6. **成片规格**：1920×1080、30fps、H.264（MP4）；旁白建议**先录屏、后配音**，音量控制在 -6dB 附近；
   字幕按 `docs/演示视频_字幕.srt` 烧入（或作为软字幕上传）。

## 2. 分镜正文

### 镜 1｜00:00–00:12（12s）片头
- **画面**：黑底标题卡 → 叠化到 `04_仿真对比实验.png` 里的空间快照特写。
- **操作**：无需交互；标题卡三行居中：`电梯微空间数字孪生` / `社交距离与交流行为耦合的多智能体仿真与治理优化` / `赛道 D · 工程设计与数字世界`。
- **口播**：「电梯轿厢：高密度、短时、密闭的微空间。在这里，社交距离究竟能不能维持？」
- **屏幕重点**：作品全称 + 赛道，3 秒内让评审知道是什么、哪个赛道。

### 镜 2｜00:12–00:30（18s）问题与目标
- **画面**：文字卡三点逐条出现（物理距离 / 社会距离 / 交流行为 → 强耦合），第三点「交流行为常被当作被动结果」标红。
- **操作**：无；若想更真实，可切到项目 README 的「问题来源与目标」段落轻轻向下滚动。
- **口播**：「物理距离、社会距离与交流行为，三者强耦合。既有研究多把交流当作被动结果，忽视了它对空间的反向作用——这正是本作品的切入点。目标：量化交流影响，给出可落地策略。」
- **屏幕重点**：讲清「别人没做什么」，为镜 6 的调制结论埋伏笔。

### 镜 3｜00:30–01:00（30s）作品内容：双模型
- **画面**：终端窗口（PowerShell）。
- **操作**：输入 `python -m elevator_twin.run` 回车；镜头跟随滚动，停在「初始空间快照」与逐 step 的 `avg_dist / violation / chat_pairs` 上。
- **口播**：「作品是电梯微空间的多智能体数字孪生。基础版：轿厢离散为 4×4 网格，建模 8 名乘客——按社交距离偏好相互排斥，按交流意愿结对攀谈。增强版换成真实尺寸，并加入楼层上下客与社会力。输出四类指标：平均最近邻距离、最小距离、违规率与交流对数。」
- **屏幕重点**：`P=乘客 / C=交流中 / .=空位` 的快照图例（评审一眼看懂网格语义）。

### 镜 4｜01:00–01:25（25s）基础版结果
- **画面**：终端继续滚到最后几行 → 切到 `05_Web界面.png` 右侧指标卡特写。
- **操作**：跑完后停在「单次仿真演示」末态；用鼠标划选高亮 `avg_dist=1.104`、`violation=1.000`、`chat_pairs=3`。
- **口播**：「基础版实跑：4×4 轿厢、8 名乘客、30 步，终端逐步打印指标。末态：平均最近邻 1.104 格，违规率 1.0，形成 3 对交流。快照里 P 是乘客，C 是正在交流的乘客。」
- **屏幕重点**：三个数字要能被暂停看清（这些数字在提交材料里可复核）。

### 镜 5｜01:25–01:55（30s）增强版：真实尺寸下的硬结论
- **画面**：终端跑 `python -m elevator_twin.model_enhanced`；右半屏叠 `elevator_twin/figs/heatmap_w0.8.png` 热力图。
- **操作**：输入命令回车，镜头停在打印出的米制指标上（**平均最近邻 ≈0.533m、最小 0.400m、违规率 1.000**）。
- **口播**：「换到真实电梯：1.6 米 × 1.4 米，格长 0.4 米。即使每位乘客都在最大化彼此距离，平均最近邻也只有 0.533 米，最小 0.4 米，违规率恒为 1.0。结论：密闭空间里，社交距离在物理上不可达；而社会力与上下客会让拥挤更动态。」
- **屏幕重点**：这是本作品最硬的发现，语速放慢、给数字 2 秒停留。

### 镜 6｜01:55–02:20（25s）核心创新：交流行为压缩距离
- **画面**：终端跑 `python -m elevator_twin.run` 的后半段——「批量对比实验」15 行表；再切 `figs/sweep.png` 曲线。
- **操作**：镜头对准对比表里「交流意愿 0.2 行（0 交流对）」与「0.8 行（4 交流对）」两处，用光标上下对比。
- **口播**：「交流行为会进一步压缩距离。低意愿：0 对交流，平均距离 1.280；高意愿：4 对交流，平均距离降到 1.0。批量实验一次给出『交流意愿 × 乘客数』15 组对比。」
- **屏幕重点**：把「交流」从被动结果讲成**主动变量**——这是创新点①。

### 镜 7｜02:20–03:00（40s）核心证据：AGH 四步闭环 + MCP 调用链
- **画面**：终端跑 `python -m elevator_twin.agh_loop`，四段标题依次滚过；画面右上角常驻角标「① → ② → ③ → ④」高亮当前步。
- **操作**：输入命令回车。停顿时机：`Agnes 模型：agnes-3.0-flash（真实调用）`（或降级提示）→ `== ① 任务规划 ==` → `== ② 能力调用 ==` 与 `MCP 调用 optimize_social_distance` 的 JSON → `== ③ 反馈处理 ==` 的空间快照 → `== ④ 结果验证 ==` 的结论行。
- **口播（已配 Key，录真实调用）**：「核心：AGH 执行闭环，规划、调用、反馈、验证四步。① 任务规划：Agnes 拆解『优化电梯社交距离』；② 能力调用：经 MCP 调用三个仿真工具——跑仿真、取快照、三档优化对比；③ 反馈处理：读取指标，不达标就调参重跑；④ 结果验证：给出策略结论。全程仅调用 Agnes 模型 agnes-3.0-flash。」
- **口播（未配 Key 的降级版，最后两句替换）**：「……③ 反馈处理：读取指标、判断是否达标；④ 结果验证：输出策略结论与治理建议。」（不要口头解释 Key，避免画面/话题涉及敏感信息）
- **屏幕重点**：MCP 三工具名 `run_simulation` / `grid_snapshot` / `optimize_social_distance` 必须被看到——这就是「至少一条工具调用链证据」。
